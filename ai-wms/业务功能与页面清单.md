# AI-WMS 业务功能与页面清单

> 来源：简道云《什么是WMS？一文讲清WMS系统所有知识》的业务描述 + 行业标准 + 本项目边界判断
> 用途：① 校验业务范围 ② 指导前端页面开发 ③ 答辩演示剧本

---

## 一、WMS 的一句话定义（直接用作答辩开场）

> **WMS 解决三个核心问题：东西放哪里、现在有多少、怎么快速出入库。**

来源：简道云文章。比"我做了个仓库管理系统"清晰十倍。

---

## 二、业务功能对照表（⚠️ 关键：标清该做/不该做）

> 简道云列的是"万能清单"（因为要卖给各种企业）。**照抄会变成"大而全"，正好踩中设计文档否定的坑。**

### ✅ 做（核心，本项目重点）

| 模块 | 功能 | 说明 |
|---|---|---|
| **基础数据** | 商品主数据（SKU、名称、规格、类目、ABC 分级、重量体积） | 用 UFMG 的 1560 个真实商品 |
| | 货位主数据（货位编码、容量、坐标） | 用 UFMG 的 1584 个货位 |
| **入库管理** | 入库单（主表）+ 入库明细（子表） | 主表-子表结构 |
| | 收货登记、上架、货位推荐 | **Agent 切入点 ①** |
| **出库管理** | 出库单 + 明细、扣减库存（防超卖） | **技术硬核点** |
| | 波次合并、拣货任务、路径规划 | **Agent 切入点 ②** |
| **库存管理** | 实时库存查询、库存流水 | |
| | 库存冻结/解冻、库存调拨、库存盘点 | 简化做 |
| **货位管理** | 货位占用状态、**货位地图可视化** | **演示亮点** |
| | 货位优化建议 | **Agent 切入点 ③** |
| **预警中心** | 库存阈值预警（低库存/呆滞） | 对应"补货预警" |
| | 异常告警 | **Agent 切入点 ④** |
| **经营看板** | 库存统计、出入库趋势、预警汇总 | 演示门面 |

### ⚪ 简化做（有就行，不做深）

| 功能 | 简化方式 |
|---|---|
| 库存盘点 | 只做"生成盘点单 + 差异调整"，不做盘点计划/循环盘点 |
| 数据报表 | 3-4 个核心图表即可，不做自定义报表 |
| 权限管理 | 只做"管理员/拣货员"两个角色 |

### ❌ 不做（明确砍掉，面试要能说出理由）

| 功能 | 为什么不做 |
|---|---|
| **销售管理** | 这是 **ERP 的职责**，WMS 只执行出库指令 |
| **采购管理** | 同上，采购决策是 ERP 的 |
| **质检追溯** | 边缘功能，时间不够，且需要质量数据 |
| **批次/效期管理** | 边缘功能；数据里也没有批次信息 |
| **多仓调拨** | 简化，先做单仓 |
| **复杂审批流** | 边缘功能 |

> **面试话术**："简道云那类模板为了卖给各种企业，把销售、采购、质检都包进来了。但按 WMS 的定位，这些是 ERP 的职责——**我明确划了边界，只做仓内作业，把省下的时间投入到并发一致性和智能决策上**。"

## 三、前端页面清单（按重要度排序）

### 🔴 第一优先：演示亮点页（这 4 个是你的差异化）

大多数 WMS 模板都没有这些——**它们是你区别于"简道云模板"的地方**。

| 页面 | 内容 | 演示价值 |
|---|---|---|
| **① 货位地图可视化** | 用 UFMG 的真实货位坐标，画出仓库平面图：巷道、货架、每个货位的占用状态（颜色区分）+ 拣货路径叠加 | ⭐⭐⭐ **最吸睛** |
| **② 补货建议页** | 预测曲线 + 建议补货量 + **成本对比**（规则补货 vs 成本优化补货） | ⭐⭐⭐ 展示"数据驱动" |
| **③ 拣货路径对比页** | 同一批订单，对比 **S形 / 最大间隙 / 返回式** 三种策略的路径图 + 行走距离 | ⭐⭐⭐ 自带实验 |
| **④ 异常告警页** | 异常列表 + 严重级别 + **LLM 生成的自然语言诊断建议** | ⭐⭐ 展示 Agent |

### 🟡 第二优先：业务主流程页

| 页面 | 内容 |
|---|---|
| 入库单列表 / 新建 / 详情 | 主表-子表（单头 + 明细行） |
| 出库单列表 / 新建 / 详情 | 同上，含"扣减库存" |
| 拣货任务页 | 任务列表 + 拣货单 + 路径图 |
| 库存查询 | 按商品/货位/状态筛选，实时数量 |
| 库存流水 | 每次变动的记录（可追溯） |
| 库存盘点 | 盘点单 + 差异调整 |

### 🟢 第三优先：基础与看板页

| 页面 | 内容 |
|---|---|
| 首页/经营看板 | 库存总量、今日出入库、预警汇总、趋势图 |
| 商品管理 | CRUD + 导入 |
| 货位管理 | CRUD + 占用状态 |
| 登录页 | |

## 四、页面设计要点（学简道云什么）

| 简道云做得好的 | 你怎么用 |
|---|---|
| **表单-流程-报表三段式**（界面→表单→流程→报表） | 你的前端也按这个组织：列表页 → 表单页 → 报表/看板 |
| **主表-子表结构**（入库单 + 明细） | 印证你 Day 1 的 ER 设计，页面也要主从展示 |
| **唯一标识字段（条形码/二维码）** | 商品和货位都有编码，**可直接生成二维码用于演示** |
| **图表看板** | 首页放 3-4 个图表：库存分布、出入库趋势、预警统计 |
| **PC + 移动（扫码）双端** | **简化**：只做 PC 端 + 一个模拟扫码的入口即可 |

## 五、答辩演示剧本（按这个顺序演）

```
1. 首页看板        → 展示库存规模（1560 商品 / 1584 货位）
2. 货位地图        → 点开仓库平面图，展示货位占用（视觉冲击）
3. 入库演示        → 新建入库单 → Agent 推荐货位 → 库存 +N
4. 出库演示        → 新建出库单 → 扣减库存（防超卖）→ 生成拣货任务
5. 路径对比        → 三种策略路径图对比 → 行走距离缩短 X%
6. 补货建议        → 预测曲线 → 建议补货量 → 成本下降 X%
7. 异常告警        → 异常列表 → LLM 诊断建议
8. 压测报告        → 1000 并发扣减，超卖 0 次
```

**前 4 步是常规 WMS 都能做的，后 4 步是你的差异。** 演示时间要重点放在后 4 步。
