# AI-WMS 智能仓储管理系统

> **Java 业务底座 + Python 智能 Agent** 的融合型仓储系统。
> 基于**真实企业 WMS 导出的生产数据**，聚焦**作业优化**而非功能堆砌。

## 四、核心设计

### 4.1 库存五字段模型

```sql
qty            现有总量      -- 货架上实际有多少（拣货时不变）
qty_allocated  已分配        -- 被订单占住
qty_picked     已拣出        -- 拣货员已取走、未发货
qty_onhold     冻结          -- 异常占用（与 allocated 分离）
qty_available  可用          -- = qty - allocated - onhold
```

**为什么需要五个字段而不是一个**：
「订单占用」和「异常冻结」是两种不同性质的库存占用，必须分开；
「拣货」时不扣总量，只在发货时扣——这才符合真实作业。

### 4.2 并发扣减防超卖

```sql
UPDATE inventory
SET qty_allocated = qty_allocated + #{qty},
    qty_available = qty_available - #{qty}
WHERE sku_id = #{skuId}
  AND location_id = #{locationId}
  AND qty_available >= #{qty}      -- ★ 判断写进 WHERE
```

**关键**：数据库执行时加行锁，把「判断够不够」和「扣减」变成**一个原子操作**，
从根上杜绝「两个请求都读到 100，各自扣 80」的超卖问题。

### 4.3 拣货路径优化（3 种行业标准策略）

从导航点数据推断出仓库是 **3 条纵向通道 + 2 个货架区块**的双区块布局，
实现了三种标准启发式并做对比实验：

| 策略 | 实测距离 | 相比基线 |
|---|---|---|
| 顺序拣货（基线） | 12127 米 | — |
| 返回式 | 11586 米 | -4.5% |
| **S形（穿越式）** | **9554 米** | **-21.2%** |
| 最大间隙 | 11586 米 | -4.5% |

**一个有意思的发现**：学术界的结论是「最大间隙在小订单量下最优」，
但在本仓库布局下 **S形更优**——因为本仓库只有 3 条通道，通道间切换成本高，
最大间隙需要从两端进入，额外的纵向移动抵消了它的优势。
**这说明算法效果依赖具体布局，不能照搬文献结论。**

#### 批量实验：100 个真实波次

单个波次的节省幅度差异很大（0% ~ 47%），取决于原始顺序是否"恰好合理"。
**只用单个波次说"省了 X%"说服力不足**，因此在 100 个真实波次上做统计：

| 指标 | 值 |
|---|---|
| 平均节省 | **12.4%** |
| 中位数节省 | 10.5% |
| 最大 / 最小 | 47.2% / 0.0% |
| S形胜出 | 66 / 100 次 |

详见 [路径优化实验报告](ai-wms/路径优化实验报告.md)

### 4.4 Agent 编排与三级降级

```
① 算法正常        → SUCCESS
② 规则桩兜底      → DEGRADED（可用但质量下降）
③ 都失败          → FAILED（生成人工工单）
```

编排器的四个职责：**任务路由 / 上下文管理 / 结果校验 / 降级决策**。

**为什么用 Workflow 而不是 Agent**（参考 Anthropic《Building Effective Agents》）：
本系统的任务路由是**确定性**的（routing→路径优化），属于 Workflow 的 Routing 模式，
用 Agent 反而增加不可控性。

## 六、快速开始

### 环境要求

- JDK 17+、Maven 3.6+
- Python 3.10+、Node.js 18+
- MySQL 8、Redis

### 一键启动（Windows）

```bash
# 1. 初始化数据库（得到干净的空系统）
mysql -u root -p < ai-wms/sql/schema.sql

# 2. 启动三个服务
start-all.bat
```

启动后访问 http://localhost:5173

> **想让系统跑起来有数据？** 两个办法：
> ① 通过系统的「**数据导入**」页面上传 Excel（商品 / 库位 / 期初库存）——这是真实 WMS 的上线流程
> ② 或者跑 `ai-wms/sql/generator/` 下的脚本批量生成初始化 SQL（用于验证算法）
>
> 详见 [ai-wms/sql/README.md](ai-wms/sql/README.md)

### 手动启动

```bash
# Java 后端（8080）
cd ai-wms/wms-backend && mvn spring-boot:run

# Python Agent（8000）
cd ai-wms/wms-agent && pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 前端（5173）
cd ai-wms/wms-frontend && npm install && npm run dev
```

访问 http://localhost:5173

> LLM 功能需要配置 API Key，见 `ai-wms/wms-agent/.env.example`。
> 未配置时自动降级为规则桩，**不影响其它功能**。
